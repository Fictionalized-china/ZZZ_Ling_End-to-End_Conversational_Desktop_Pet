# 铃宝桌宠聊天开发计划

更新日期：2026-10-09。项目目录：`E:\TAPWORK\大肥鱼`。

目标是提供同一个免安装 Windows x64 exe，让两台普通 Win10／Win11 电脑通过 Cloudflare 临时配对并交换文字、图片和剪贴板截图。界面以桌宠为主体。只有双方在线且都未选择忙碌时才能聊天。

## 已确认需求

| 范围     | 约定                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 人数     | 每个配对最多两个客户端，没有联系人、账号系统或群聊                     |
| 生命周期 | 配对只在本次进程中有效；关闭程序或取消配对后重新配对；短暂断网自动重连 |
| 消息     | 文字、图片、截图粘贴，只转发，不保存聊天记录                           |
| 状态按钮 | 选择自己的在线或忙碌；断网、未配对和对方离线显示综合不在线             |
| 菜单     | 六个动作的禁用复选框、配对、取消配对、开机自启、退出                   |
| 桌宠     | 可拖动；双击后右上方弹出输入框，点击发送按钮发送                       |
| 其余按钮 | 调整大小、置顶开关；置顶同时作用于桌宠、菜单、输入框和图片预览         |
| 素材     | 已收到六个动作文件夹，每个 8 帧透明 PNG，共 48 帧，约 1.6 MB           |
| 部署     | Cloudflare；实际使用网络在中国大陆；打包后无需另装 Node.js 或运行时    |

## 状态和交互

配对关系、连接情况和用户选择分别管理，避免把网络连接等同于愿意聊天。综合状态的优先级为：不在线 > 忙碌 > 在线。

| 情况                       | 综合状态 | 发送和接收新消息 |
| -------------------------- | -------- | ---------------- |
| 未配对，或任意一方连接失效 | 不在线   | 禁止             |
| 双方连通，至少一方选择忙碌 | 忙碌     | 禁止             |
| 双方连通，均选择在线       | 在线     | 允许             |

状态通知和心跳在忙碌时继续传输。禁聊由服务器和客户端共同检查。服务端按收到事件的顺序判断状态切换和消息发送；已完整收到的内容不撤回，状态切换后的新内容不继续投递。尚未发送的草稿在忙碌期间保留，解除忙碌不自动发送。

启动时默认选择在线，但未配对仍显示不在线。第一次打开配对菜单时可生成“我的配对码”，另一台电脑输入此码并确认。邀请一次使用，10 分钟未使用则失效；第三个客户端不得加入。配对凭证只保存在当前进程内，开机自启不恢复上一次配对。

接收文字显示气泡，接收图片显示缩略图并允许打开预览；最近消息仅保留在本次会话内存中。取消配对清空本次会话，切换对象时不会显示上一个对象的内容。

调整大小先提供 75%、100%、125%、150% 四档。输入框优先在桌宠右上方，靠近屏幕边缘时自动换边。菜单和输入框展开时暂停动作切换。置顶覆盖普通应用窗口，不承诺覆盖系统安全桌面、锁屏或独占全屏。

## 技术方案与依据

- 客户端：Electron、TypeScript、React、Vite。主进程管理网络、窗口、剪贴板和系统设置；渲染进程只负责交互，通过受限 preload API 调用主进程。
- 中继：Cloudflare Workers + 一个配对对应一个 Durable Object，使用 WSS。服务端统一控制配对成员、在线状态与发消息权限。[官方 WebSocket 说明](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)
- 打包：electron-builder 的 portable 目标，生成单个免安装 exe。程序启动时会解包运行组件；这不代表零临时文件。[官方打包配置](https://www.electron.build/docs/configuration/)
- 桌宠：透明无边框窗口；尺寸由按钮控制，避免依赖透明窗口的原生边框缩放。程序化大小调整需要在 Win10／Win11 实测。[透明窗口限制](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles/)
- 当前使用 x64；依赖通过锁文件固定，版本是否能打包和运行以实际检查为准。

不引入 D1、R2 或消息数据库。Durable Object 可保存配对控制元数据，例如凭证摘要、邀请有效期和取消标记，用于重连与拒绝第三人；其中不包含聊天正文或图片。会话取消后销毁控制数据，异常离开留下的元数据按过期策略清理。

## 消息与数据边界

- 文字和图片只经过传输缓冲区与客户端内存；不用 localStorage、IndexedDB 或文件保存消息。
- 可记住的本地设置仅包含大小、位置、置顶、动作禁用列表、开机自启和中继地址。
- 日志不输出文字正文、图片、配对码或连接凭证；Cloudflare 观测日志默认关闭。
- 首版传输使用 TLS，并非端到端加密；中继在转发时可以处理正文。
- 图片首版以 PNG 作为传输格式，在客户端内存中读取、校验和规范化。初始单张传输上限 8 MiB、最长边 4096 像素；发送前预览，超过限制明确提示。
- 图片通过 WebSocket 二进制消息直接转发，不先上传为对象存储链接。8 MiB 应用上限低于当前 Durable Object 32 MiB 入站 WebSocket 上限。[官方限制](https://developers.cloudflare.com/durable-objects/platform/limits/)
- 状态快照带版本，消息带唯一 ID。对方确认接收后才显示“已送达”；断网或超时不误报成功，不自动排队补发。
- 不删除用户原本选取的图片文件或系统剪贴板。无聊天持久化是应用行为边界，不保证操作系统交换内存或崩溃转储的取证清除。
